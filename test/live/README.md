# Дни доставки: проверка Flutter и бэкенда на реальном сервере

Для журнала событий есть отдельный набор `test/live/audit_events_live_test.dart`.
Он включается через `LIVE_AUDIT_EVENTS=true`, использует те же `LIVE_API_URL`,
`LIVE_API_USERNAME` и `LIVE_API_PASSWORD`. Запуск: `flutter test test/live/audit_events_live_test.dart`.
Проверка создаёт товар с уникальной меткой, переименовывает его, меняет цену,
деактивирует и проверяет API истории, курсор и настоящий экран Flutter. Товар
остаётся деактивированным, события сохраняются; база не пересоздаётся.

Этот набор запускается по запросу и использует настоящие Flutter-виджеты, репозитории, аутентификацию и HTTP-запросы.
Он не запускает и не перезапускает бэкенд, не подключается напрямую к PostgreSQL и не сбрасывает базу данных.
Обычный запуск `flutter test` пропускает этот набор.

Запускайте его против бэкенда разработки, в котором уже есть хотя бы один документ доставки или самовывоза.
Передайте следующие переменные окружения, не добавляя учётные данные в коммит:

- `LIVE_DELIVERY_DAYS=true`
- `LIVE_API_URL=http://127.0.0.1:8000` (необязательно)
- `LIVE_API_USERNAME` и `LIVE_API_PASSWORD` для разрешённой учётной записи разработки.

Из проекта Flutter выполните `flutter test test/live/delivery_days_live_test.dart`.
Запускатель с фальшивыми часами для Windows преобразует `localhost` в IPv4 и использует настоящие HTTP-клиенты и асинхронный ввод-вывод.

Набор создаёт записи и документы с уникальными метками `LIVE-<timestamp>`, проверяет оба способа создания документов,
сохранённые названия после переименования в каталоге, изменение цены и количества, отмену и восстановление,
перенос между датами, границы календаря, диалог для пустого дня и пустой документ с прошедшей датой.
PDF проверяется отдельно от виджетного сценария с фальшивыми часами на основе сохранённого снимка документа.
Артефакты записываются в игнорируемую Git папку `build/live-delivery-days/`.

Очистка переносит только созданные набором документы обратно в исходный диапазон календаря,
отменяет их и деактивирует созданные набором записи. Отменённые документы и история изменений остаются в базе,
поскольку публичный API намеренно не поддерживает физическое удаление.
Дождитесь завершения процесса, чтобы выполнилась очистка в блоке `finally`: прерывание может оставить тестовые записи активными.
