# Разделение истории клиентов и документов

Статус: согласованный контракт, реализация ещё не начата.

**Единый контракт для backend и Flutter:**

[delivery-history-separation.md](https://github.com/boradydev/mountain_fairytale_backend/blob/codex/delivery-history/docs/contracts/delivery-history-separation.md)

Ветка обоих проектов: `codex/delivery-history`.

При реализации обязательно открыть указанный контракт и свериться с текущими компонентами `DeliveryHistoryScreen`, `DeliveryHistoryProvider`, `RoutePointsList`, `AppDateRangeDialog`, `DayDocumentsDialog`, `RouteSheetPdfBuilder` и моделями точек.

Главные ограничения:
- В истории клиентов — одна карточка на точку доставки, поиск по текущим и историческим реквизитам, две соседние карточки.
- В истории документов — целые маршруты и самовывозы с фильтром типа, без группировки по дням.
- Исторические имя, телефон, адрес, уточнение доставки и ID представителя фиксируются на точке; имена представителей разрешаются из справочника.
- Выбор представителя разрешён при создании маршрута, но не при просмотре или редактировании сохранённого.
- Печатная форма использует исторические реквизиты, а не актуальную карточку клиента.
- Пагинация по 50 карточек с автоподгрузкой; использовать согласованную сортировку.
- Не менять текущую логику начисления комиссий; не делать релиз и не применять миграции на production без отдельного решения.

Это файл-указатель, не отдельный контракт: при расхождениях источником требований является ссылка выше.
