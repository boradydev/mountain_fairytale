# Общий раздел справочников

Ветка Flutter: `codex/entity-directories`, создана от текущих изменений
репетиции после коммитов пользователя. Коммиты выполняет пользователь.
Backend-код не менялся, ветка backend не переключалась.

## Поведение

- В общей навигации появился таб «Справочники», доступный сотрудникам
  и администратору. Как и остальные разделы, создаётся при первом открытии.
- Сегментированный переключатель содержит продукцию, водителей, автомобили,
  способы оплаты и торговых представителей. Поиска нет.
- Чекбокс «Деактивированные» включает неактивные записи вместе с активными.
  Значение фильтра и список хранятся отдельно для каждого справочника.
  Список имеет отдельный ключ прокрутки для каждого раздела.
- По ручному замечанию пользователя чекбокс расположен непосредственно
  рядом с сегментированным переключателем. Та же компоновка применена
  на экране комиссий: переключатель и фильтр вместе слева, месяц справа.
  Для недостаточной ширины сохранён перенос. После изменения прошли
  11 тестов справочников и 13 тестов комиссий, анализ без замечаний.
- Первый элемент — карточка добавления. Карточка сущности показывает имя,
  статус «Активен»/«Деактивирован» и доступные основные данные: цену товара,
  номер и пробег машины, телефон и ставку представителя.
- По ручному замечанию пользователя статус вынесен к правому краю во всех
  пяти справочниках. Переиспользован CommissionPersonHeader — тот же заголовок,
  что в карточках комиссий. После правки 11 тестов справочников прошли,
  анализ изменённого экрана без замечаний.
- Нажатие открывает существующий ProductDialog, DriverDialog, CarDialog,
  PaymentMethodDialog либо SalesRepDialog. Перед редактированием запись
  перечитывается. Доступны прежние проверки дубликатов, поля, сохранение,
  активация и деактивация, переход к похожей записи.
- В режиме справочника скрыты команды выбора для маршрута/клиента;
  подтверждение активации говорит только об активации. В CarDialog добавлена
  возможность активировать ранее деактивированную машину из её редактора.
- Формы получают отдельный новый RouteConstructorProvider с теми же
  репозиториями. Это адаптация к существующим формам, которые используют
  его для операций над сущностями. Данные открытого пользовательского
  маршрута/самовывоза не передаются в этот экземпляр. Экземпляр уничтожается
  после закрытия формы, документ не создаётся и edit lock не запрашивается.
- После закрытия формы перечитывается соответствующий список. При возврате
  в общий таб перечитывается текущий раздел. Ошибки загрузки допускают повтор;
  устаревший ответ не перезаписывает результат нового фильтра.

Переиспользованы AppListSectionHeader, LabeledCheckboxToggle, AddActionButton,
AppBaseCard, ActiveStatusLabel, все пять существующих диалогов сущностей,
AppPrimaryButton/AppSecondaryButton и подтверждения активации с дополнительным
параметром. Новых общих виджетов нет.

## API и данные

Используются прежние репозитории. В SalesRepresentativeApiRepository добавлено
чтение списка через существующий GET /protected/sales-representatives с
include_deactivated. Контракт проверен по router/schemas backend:
data.salesRepresentatives, UUID, camelCase, активные по умолчанию.
Смена активности остаётся PATCH isActive; физическое удаление не добавлено.
База и исторические документы не мигрировали и не пересоздавались.

## Проверки

- Полный Flutter-набор: 354 теста прошли, 5 live-тестов штатно пропущены.
- Анализ всех изменённых Dart-файлов: без замечаний.
- Для всех пяти сущностей проверены создание, отмена создания, редактирование,
  ошибка записи и повтор, деактивация, показ неактивных и обратная активация.
- Проверено, что водитель, автомобиль, товары, сумма открытого документа
  остаются прежними; вызовов сохранения документа и получения блокировки нет.
- Проверены независимость фильтров, ошибка чтения/повтор и устаревший ответ.
- AppShell проверен для сотрудника и администратора: справочники доступны,
  загрузка отложена до открытия, остальные вкладки сохраняют своё поведение.
- API-метод списка представителей проверен на пути, параметрах и конверте.
- На локальном API выполнено только чтение активных/всех записей каждого
  справочника: все пять запросов работают, неактивный представитель включается
  по фильтру. Тестовые записи агентом не создавались.

## Ручная проверка (ожидается)

1. Открыть «Справочники», переключить пять разделов. В каждом первой
   карточка добавления, на сущностях виден статус; поля поиска нет.
2. Открыть карточки существующих сущностей и закрыть через ОК/Отмена:
   открываются привычные диалоги без создания документа.
3. На тестовых записях проверить создание, переименование и смену активности.
   Неактивная запись исчезает из обычного списка и видна через чекбокс.
4. У представителей проверить переключение между активными и всеми,
   сохранение фильтра после переключения разделов и возврата в таб.
5. Проверить быстрые формы из документа: их прежнее поведение выбора
   сохранено, а исторические цены/имена документа не изменились.
