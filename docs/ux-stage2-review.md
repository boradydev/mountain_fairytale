# Этап 2: оборот сотрудников, единые подписи и подсказки

Ветка обоих проектов: `codex/ux-rehearsal-fixes`. Коммиты делает пользователь.

## Изменения UX-10

- Backend возвращает отдельный `summary.employeeTurnover`: оборот активных
  документов выбранного месяца, у которых есть сохранённое участие сотрудников.
  Каждый документ учитывается один раз, независимо от количества получателей.
  Одинаковые суммы разных документов не схлопываются.
- Пустая ставка не создаёт участия; явно заданные 0% учитываются — пользователь
  подтвердил сохранение действующего правила. Текущая ставка и деактивация
  сотрудника не переписывают историю. Отмена/восстановление и перенос даты
  меняют оборот согласно активности и плановой дате документа.
- «Общий оборот» не изменён. «Оборот сотрудников» использует новый агрегат,
  а не общий оборот и не сумму персональных баз.
- В обоих вариантах сводки используются «Оборот представителей» /
  «Оборот сотрудников». На карточках представителей и сотрудников,
  в детализации — «Оборотная база» / «К выплате».
- Все показатели шапки и карточек получили hover-подсказки: состав, период
  и назначение. Для текущего числа закреплённых клиентов и исторических ставок
  пояснения отдельно уточняют смысл. Подсказка базы в разбивке ставки относится
  только к этой ставке.
- Переиспользованы `CommissionMetric`, `CommissionRates`, элементы сводки
  и штатный `Tooltip`. Новых форм и reusable-виджетов не добавлено;
  тексты подсказок собраны в одной функции внутри фичи комиссий.

## Проверки

- Backend: 16 тестов комиссий, необязательных ставок, нового оборота и денег — успешно.
- Flutter: полный набор 311 успешных, 5 live-тестов штатно пропущены.
  Включены проверки реального наведения мыши, переключения режимов,
  отдельного агрегата, светлой/тёмной темы и увеличенного текста.
- Миграции для второго этапа не требуются, сохранённые данные не меняются.
  Backend должен обновиться до подключения нового Flutter: клиент ожидает
  `employeeTurnover` в сводке. Существующий Flutter игнорирует новое поле API.
- Ruff и анализ изменённой Flutter-фичи — без замечаний. Приложение и API
  перезапущены целиком. На базе репетиции независимо через SQL и API подтверждены:
  7 сохранённых документов, общий оборот октября 6250 ₽, оборот сотрудников
  2100 ₽, выплаты представителям 210 ₽ и сотрудникам 42 ₽. У operator_test
  персональная база 2100 ₽ и начисление 42 ₽. Бизнес-данные не менялись.

## Ручная проверка на базе репетиции

1. Открыть «Комиссии», выбрать октябрь 2026, переключить сотрудников и представителей.
2. Сверить «Оборот сотрудников» с документами, созданными после назначения
   operator_test ставки 2%, без добавления старых документов задним числом.
3. Проверить подписи и подсказки наведением на заголовки и суммы сводки,
   карточек обоих типов и разбивки ставок.
4. Включить/выключить показ деактивированных: сводные суммы не меняются.
5. По желанию отменить один из учитываемых самовывозов на 700 ₽ и восстановить:
   оборот сотрудников уменьшается на 700 ₽ и возвращается. Не создавать
   новые документы для этой проверки.

Суммы и названия нужно подтвердить в интерфейсе перед коммитами. Другие
замечания комиссий (добавление представителя, активация из карточки и размер
диалога передачи) в этот этап не включены.
