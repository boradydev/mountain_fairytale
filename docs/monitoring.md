# Диагностика Flutter через GlitchTip

Sentry Flutter SDK 10.2.0 отправляет Dart/Flutter-ошибки напрямую в локальный
GlitchTip. FastAPI сообщает только публичную конфигурацию через
`GET /public/monitoring/config` и не пересылает события.

Источник конфигурации — выбранный пользователем URL API. DSN строится из того
же хоста, публичного ключа/проекта и порта мониторинга (по умолчанию 8080).
Для LAN/VPN отдельная сборка, ввод DSN или переключатель не требуются.
При смене сервера прежний отправитель закрывается, запоздавшая конфигурация
не применяется. Неудача загрузки не блокирует интерфейс: повтор через минуту.
Отключённая конфигурация не включает SDK; старый backend с 404 поддерживается.

Собираются необработанные Dart/Flutter-исключения, ошибки JSON-декодирования,
формирования PDF и печати. Сохраняются тип, файл/функция/строка, версия и окружение.
`X-Request-ID` из API сохраняется в HTTP-ответе/ApiException и диагностике
некорректного JSON. Операции PDF/печати отмечены фиксированными техническими тегами.
Значения исключений, request body/headers/query, user, extras, breadcrumbs,
локальные переменные и абсолютные пути пользователя не отправляются.
ApiException, обычная недоступность сети, таймауты и отмена пользователем
не считаются авариями. HTTP 5xx диагностируются backend, не дублируются во Flutter.

Скриншоты, native crash capture, performance/profiling, сессии и дисковая очередь
не включены. Проверены Dart-стеки Windows; это не гарантия диагностики падения
нативной DLL/драйвера. До получения конфигурации и при недоступности приёмника
часть событий может потеряться. Очередь SDK в памяти ограничена 30 событиями,
дубли типа/стека — одним событием в минуту (не более 128 сохранённых сигнатур).
Обычная работа приложения не зависит от успешной отправки.

Для новых обработанных неожиданных ошибок использовать `reportUnexpected`
в конечной точке обработки с исходным stack trace. Не добавлять отправку на каждом
слое и не записывать параметры документов/ФИО в теги. Изменений UI не требуется.

## Проверки и выпуск

```sh
flutter test test/core/monitoring_test.dart
flutter analyze lib test --no-fatal-infos --no-fatal-warnings
flutter build windows --release
```

Opt-in приёмка `test/live/monitoring_live_test.dart` отправляет тестовое событие
в **реальный** GlitchTip через локальный тестовый HTTP relay (он не используется
в приложении). Нужны только публичный ключ Flutter-проекта и его идентификатор:

```sh
flutter test test/live/monitoring_live_test.dart \
  --dart-define=LIVE_MONITORING=true \
  --dart-define=LIVE_MONITORING_KEY=ПУБЛИЧНЫЙ_HEX_КЛЮЧ \
  --dart-define=LIVE_MONITORING_PROJECT=ИДЕНТИФИКАТОР \
  --dart-define=LIVE_MONITORING_HOST=10.77.50.11
```

Проверяются версия/стек, удаление приватного тестового маркера и прекращение
отправки после отключения конфигурации. Без флага тест пропускается и не
обращается к клиентской инфраструктуре. Production DSN, пароли и admin-токены
в исходники/CI не добавлять. Никакой dart-define для DSN пользовательской сборки
не требуется: настройка получается от выбранного API.

Код проверен 25 октября 2026. Для рабочих ПК сначала выпустить backend с новым
endpoint штатным workflow, затем Flutter через существующий канал обновлений.
Приёмочное событие не означает, что уже установленная старая версия поддерживает SDK.
