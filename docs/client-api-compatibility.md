# Совместимость приложения с API

Реализация подготовлена 28 октября 2026 года; публикация выпуска не выполнена.
Основной контракт находится в backend:
`docs/contracts/client-api-compatibility-plan.md`.

Приложение работает с одним обновляемым API. При запуске и смене сервера
получает `/public/app-info`, затем допускает вход и рабочие запросы.
Версия и build читаются из установленной сборки через `package_info_plus`.
Общий `HttpTransport` передаёт `X-Client-Version` и `X-Client-Build`, в том числе
для login, refresh и long polling. Версия в `User-Agent` также обновляется.

Backend хранит минимум в `client_compatibility.toml`; начальное значение —
`1.1.0` для выпуска backend `1.0.0`. Новые ENV и миграции не требуются. Существующие настройки адреса API
и GitHub updater сохраняются. Эксплуатационные health/app-info/monitoring
методы допускают обращения без заголовка версии.

Если версия ниже минимума, сервер возвращает `409 CLIENT_UPDATE_REQUIRED`
до операции. Flutter включает единый экран требования обновления и сбрасывает
формы вместе с несохранёнными данными. Сохранённые серверные документы остаются.
Токены не очищаются; отказ не запускает refresh. Рабочие экраны и их фоновые
запросы прекращаются, новые рабочие запросы блокируются локально.

На экране доступны обновление, повторная проверка, меню подключения и закрытие.
Отмена или ошибка установки не разрешает работу. Установка по-прежнему
подтверждается пользователем и выполняется существующим подписанным updater.
Версия приложения, сервера и минимум также видны в меню приложения.

Совместимый Flutter продолжает работать и обновляется добровольно. Визуальные
изменения можно выпускать самостоятельно. Flutter с новой серверной функцией
публикуется только после установки нужного API. При несовместимом изменении
выпуск обеих частей завершается вне рабочего времени до начала работы.

Обычная недоступность API во время работы обрабатывается существующим кодом.
Новая система повторов не добавляется; после восстановления сервера перезапуск
приложения не требуется. Стартовая проверка имеет кнопку повтора.
Неопределённый результат записи автоматически не повторяется.

Проверки: `flutter test test/app_compatibility`, затем штатный
`flutter test --exclude-tags live_api`. Отдельные live-проверки/служебные клиенты,
создающие собственный транспорт без запуска приложения, должны явно передавать
метаданные клиента; доступ к рабочим методам без версии сервер отклоняет.

Для выпуска в `pubspec.yaml` выставлено `1.1.0+1`, подготовлены release notes.
Тег Flutter — `v1.1.0`; номер сборки CI подставляет самостоятельно.
Backend `1.0.0` устанавливается до публикации Flutter `1.1.0`.
Теги и публикация выполняются владельцем; уже опубликованные тег и установщик
повторно не используются и не заменяются.
